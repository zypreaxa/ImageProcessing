1  Assignment Description
This document (12 pages in total) describes a preliminary version the first compulsory assign-
ment for the course “Introduction to Image Analysis” taking place at Faculty of Mathematics
and  Informatics,  Vilnius  University,  Lithuania,  Autumn  2026.   This  is  the  first  of  a  total  of
three  assignments;  it  will  be  scored  between  0  and  100  points  and  weighted  by  30%  in  the
overall grade for the course.
In short, the assignment concerns the practical exercises of the first five weeks of the course,
and, as such, can be interpreted as giving a summary of the material covered in the course so
far and the practical implementation of it.
Engineering and Computer Science students must use C++ as implementation language while
Data Scientists, System Biologists and pure Mathematics students are allowed to choose be-
tween C++ and Python.  The choice of implementation language used in Compulsory Assign-
ment 1 must be used for upcoming compulsory assignments 2 and 3 also.  See section 1.1 for
specific restrictions and which implementation libraries are allowed.
Although the assignment covers the practical exercises already handed out, some clarifications
and minor adjustments are described in the following exercises.  Also listed is the data handed
out for each topic, but you may use any image you feel is best for your examples.  However,
some exercises will use designated images, which are either from the handouts or available in a
zip file accompanying this document.
The student must include a written report with explanations of the background material, ex-
plained for an audience assumed not already familiar with it.  Additionally, it must describe
how the material was implemented including any choices made and how special cases were han-
dled.  The student may freely reorder the topics, exercises and descriptions of implementations
to optimize the understanding of the material as a whole.
Besides the report, the implemented code (C++ or Python) must also be handed in. The report
must include descriptions of how each example can be run on a command line in Ubuntu/Fedora
Linux.  For C++ code you must also describe how to compile it using a combination of make
and qmake.  See Appendix A for details.
The report must be submitted in pdf and uploaded together with the code as a single zip-file
in the VU Emokymai system.
Deadline will be around the 23rd of October, but will be decided later.  Also, a few changes
may come to each assignment topic, but they will be finalized in the week the topic is covered
in the lectures.

2.2  Intensity Transformations
Purpose:  Gain practical experience with:
•  Image intensity histograms.
•  Image  intensity  transformations  and  how  they  affect  the  image  by  looking  at  the
intensity histograms.
•  Precision for intermediate calculations.
Implementations and Tasks:  Only 8 bit grayscale images will be used, and so it’s natural
to  use  an unsigned char  or  equivalent  8-bit  type  to  hold  pixel  intensities.   You  must
describe your considerations regarding use of a different number format, e.g. floats, for
intermediate calculations and any additional steps needed to conform with visualization
of 8 bit images.
•  Implement the power law for intensities (you may disregard the constant c)
Describe your implementation.
Visualize the effect of different values of the γ parameter.
(Hint:  For some value of γ  describe what results you expect (and why) and then
explain if your implementation does output this or what could be the short-coming
if it does not.)
•  Implement piece-wise linear intensity transformations.
Give  an  example  (and  visualize  the  results  of  applying)  one  histogram  stretching
transformation and one thresholding.
•  Implement histogram calculation for grayscale images.
•  Implement histogram equalization.
Compare the piece-wise linear transformation applied above to the histogram equal-
ization function.
Explain how/if the number of intensity values changes when performing a histogram
equalization.
•  Implement lookup table intensity transformations and use it to perform the intensity
transformations above.
Discuss the differences between evaluating the intensity transform for each pixel and
using a look-up table.
Are there any image/pixel formats that are not well suited to application of a look-up
table?
Data handout:  Images in ImgSet2.zip

2.3  Spatial Filtering and Multistep Image Processing
Purpose:  Gain practical experience with:
•  Image filtering in the spatial domain.
•  Multi-step image processing.
Implementations and Tasks:  Only  8  bit  grayscale  images  will  be  loaded  and  visualized.
Intermediate results will be calculated using images that holds pixel intensities in floats.
Some form of conversion back to the original 8 bit image format is needed as viewing of
only 8 bits images will be allowed.
•  Implement  separate  separate  image  arrays  (or  image  classes)  for  pixel  intensities
stored in 8-bit/unsigned char and float,  and methods to convert between the
two formats.  The conversion steps must be described in the report.
•  Illustrate working image blurring by spatial filtering.
•  Explain  how  linear  filters  can  be  used  to  implement  numerical  approximations  of
(partial) derivative operators.  Give examples of this and of (magnitude of) gradient
and the Laplacian.
•  Illustrate image sharpening by unsharp mask and by using an intermediate Laplacian
calculation.  Comment on benefits/drawbacks between the two approaches.
•  Redo example 3-43 using multistep image processing.  Describe handling of interme-
diate results.
Data handout:  Images in ImgSet3.zip, which include example 3-43.

2.4  Image Transformations
Purpose:  Gain practical experience with:
•  Different image coordinate system (both 2D world and local coordinates, 2D pixels
indices).
•  Composite  transformations  for  transforming  between  image  spaces  and  to  apply
arbitrary affine transformations.
•  Application of affine transformations to 2D images.
•  Image interpolation schemes for constructing result of affine image transformations.
Implementations and Tasks:Explain, implement and give examples of the following:
•  Assigning coordinate systems to images and calculation of index-to-local and local-
to-world transformations taking pixel size into account.
•  Composite affine transformations.
•  Nearest Neighbor and Bi-linear Interpolation for visualization of transformed images.
•  Visualize different affine transformations using any appropriate image.
Use both nearest and bilinear interpolation types.
•  Use the above for quality assurance of AI classification of kidney histology images
as described on the following page.
Data:  Images handed out in ImgSet4.zip and the images in the accompanying BXX.zip file.

The  reason  for  training  separate  AI  classifiers  was  to  exploit  the  possibility  to  use  different
pixel sizes for the AI training patches independently of other tissue types.  However, a price is
that a pixel may be assigned multiple tissue classes.  A quality assurance measurement is then
the overlap of different tissues classes, which should ideally be 0.  Calculating this per glomeruli
will allow investigating if the glomeri itself has impact on the AI classifiers, but it is a separate
task not considered here.
So, you are asked to calculate how much the Tubules and PTC overlaps with the Glomeruli
given in Table 1.  For brevity, you may consider only Glomeruli with id’s 3, 4 and 5.  The overlap
must be reported as area in both number of pixels andμm.  Hint:  First create and visualize
overlays of the glomeruli regions on top of the WSI for each tissue class.  Then  calculate the
overlaps.  Also, calculate the overlaps in the grid/resolution/pixel size of the acquired WSI.
